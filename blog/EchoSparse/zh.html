EchoSparse：复用上一去噪步的统计量，用多级近似代替丢弃，并打包稀疏 attention 的计算

作者 EchoSparse Team

视频扩散模型的 self-attention 序列很长。以 Wan2.1-14B 生成 720p、81 帧视频为例，每层 attention 要处理约 7.56 万个 token。对一个 query 来说，很多 KV 块的贡献都很小。

LLM 上已有不少高稀疏度的做法，例如滑动窗口 attention（SWA），以及 GDN、KDA 这类线性 attention。这些做法基本都在训练时就写进了模型结构。本文讨论另一种情况：视频 DiT 已经用稠密 softmax attention 训练完成，我们不重新训练，直接替换它的 attention。视频里一个 query 的概率质量往往分散在时空方向的很多块上。每个块的质量都小，加起来的占比却不可忽略。直接丢掉这些块，softmax 的分子和分母都会改变，整行的加权方式也随之改变。不重新训练时，这种改变通常会在生成的画面上表现出来。在训练阶段就引入 SWA 或线性 attention 的视频模型属于另一类方法，本文不涉及。

我们的工作以两项已有方法为基础：Haopeng Li 等人的 PISA（论文，代码），以及 Sol-Attn（项目页，论文）。两者对未选中的块都做近似计算。PISA 把每个块的处理从“保留或丢弃”改为“精确计算或近似”：重要的块精确计算，其余块用块内 Taylor 展开近似。Sol-Attn 给未选中的块加零阶补偿，并用一张 query token 对池化 key 块的 score tile 选择块。两种方法的补偿项都计入 attention 的分子和分母，多个块的代表向量也都已经拼在一起做 GEMM。

EchoSparse 在此基础上做了三项改动：

  1. 复用上一步的统计量。 相邻两个去噪步之间，每个 attention 行的统计量变化很小。因此上一步的 LSE（log-sum-exp，即 softmax 分母的对数）和每个块的质量（block mass，即一个块分到的 attention 概率之和）可以直接用在本步。FlashAttention 的内循环在每个 KV tile 上都要做三项计算：行最大值归约、缩放系数计算和旧累积量的重缩放。把 LSE 用作 softmax 的固定偏移后，这三项都可以去掉。块质量则给出块之间的相对重要性。
  2. 多层级代表块。 一个块用多少个代表参与计算（记为 mbm_bmb​）可以在 1、2、4、8 直到 64 之间选择，64 就是原始 token。代表越多，近似越精细，开销也越大。目前的实现只用了 1、4、64 三档。
  3. 代表块的打包（packing）。 代表项的计算很零碎，例如 (Bq×d)(d×1)(B_q\times d)(d\times1)(Bq​×d)(d×1)、(Bq×d)(d×1)(B_q\times d)(d\times1)(Bq​×d)(d×1)、(Bq×d)(d×4)(B_q\times d)(d\times4)(Bq​×d)(d×4)。它们可以合成一次 (Bq×d)(d×[1+1+4])(B_q\times d)(d\times[1+1+4])(Bq​×d)(d×[1+1+4]) 的计算。拼接、搬运和同步本身也有开销，所以数据要组织成足够宽的 tile，并让搬运和计算同时进行。

EchoSparse 保持零阶近似，把一个块分成更多组，组数 mbm_bmb​ 可变（见第 3 节）。

2. 复用上一步的 LSE

FlashAttention 类 kernel 按 KV tile 依次扫描，用 online softmax 维护每行的运行最大值。实现中统一使用 exp⁡2\exp_2exp2​，本节的 sijs_{ij}sij​ 都已乘过 log⁡2e\log_2 elog2​e。对每个 KV tile，每一行 iii 要计算：

minew=max⁡(mi, max⁡jsij),αi=2 mi−minew,pij=2 sij−minew,ℓi←αi ℓi+∑jpij,Oi←αi Oi+∑jpijvj. \begin{aligned} m_i^{\text{new}}&=\max\bigl(m_i,\ \max_j s_{ij}\bigr),\qquad \alpha_i=2^{\,m_i-m_i^{\text{new}}},\qquad p_{ij}=2^{\,s_{ij}-m_i^{\text{new}}},\\ \ell_i&\leftarrow\alpha_i\,\ell_i+\sum_j p_{ij},\qquad O_i\leftarrow\alpha_i\,O_i+\sum_j p_{ij}v_j . \end{aligned} minew​ℓi​​=max(mi​, jmax​sij​),αi​=2mi​−minew​,pij​=2sij​−minew​,←αi​ℓi​+j∑​pij​,Oi​←αi​Oi​+j∑​pij​vj​.​

如果每行事先给定一个固定偏移 a^i\hat a_ia^i​，循环简化为

pij=2 sij−a^i,ℓi←ℓi+∑jpij,Oi←Oi+∑jpijvj. p_{ij}=2^{\,s_{ij}-\hat a_i},\qquad \ell_i\leftarrow\ell_i+\sum_jp_{ij},\qquad O_i\leftarrow O_i+\sum_jp_{ij}v_j . pij​=2sij​−a^i​,ℓi​←ℓi​+j∑​pij​,Oi​←Oi​+j∑​pij​vj​.

EchoSparse 取 a^i\hat a_ia^i​ 为上一去噪步中同一层、同一 CFG 分支、同一行的 log2 LSE。下面对比固定偏移路径和 online 回退路径。

参数取 BM=128、BN=64、D=Dv=128，scale2=log2(e)/sqrt(D)。原始 token 的 log_count 为 0，代表项为 log⁡2n\log_2 nlog2​n。SM120 主线把 64-token 块分成两个 32-key 半块，H100 实验路径使用 64 宽的 tile。

# Online softmax
m = tl.full((BM,), -float("inf"), tl.float32)
l = tl.zeros((BM,), tl.float32)
acc = tl.zeros((BM, Dv), tl.float32)
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    block_max = tl.max(s2, axis=1)
    m_new = tl.maximum(m, block_max)
    alpha = tl.exp2(m - m_new)
    p = tl.exp2(s2 - m_new[:, None])
    l = l * alpha + tl.sum(p, axis=1)
    acc = acc * alpha[:, None]
    acc = tl.dot(p.to(tl.bfloat16), v, acc)
    m = m_new
out = acc / l[:, None]
new_lse2 = m + tl.log2(l)

# Fixed offset
prior2 = tl.load(PREV_LSE2 + rows * H + head)
l = tl.zeros((BM,), tl.float32)
acc = tl.zeros((BM, Dv), tl.float32)
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    p = tl.exp2(s2 - prior2[:, None])
    l += tl.sum(p, axis=1)
    acc = tl.dot(p.to(tl.bfloat16), v, acc)
out = acc / l[:, None]
new_lse2 = prior2 + tl.log2(l)

每个 KV tile 省掉的计算有：

  • 行最大值归约：对 128 行、每行 64 个元素求最大值。逻辑上约 128×63128\times63128×63 次比较，加上 lane 间的归约，另有 128 次运行最大值的比较。
  • 缩放系数：128 个 αi=2mi−minew\alpha_i=2^{m_i-m_i^{\text{new}}}αi​=2mi​−minew​。128×64=8192128\times64=8192128×64=8192 个 pijp_{ij}pij​ 的 exp⁡2\exp_2exp2​ 仍然要算。
  • 旧累积量的重缩放：分母 128 个元素，输出累积器 128×128=16,384128\times128=16{,}384128×128=16,384 个 FP32 元素。

这里统计的是逻辑运算量，和机器指令数并不一一对应。累积器位于片上，这些运算也不产生显存流量。它们在每个 KV tile 上都会重复：密度为 0.10 时，每个 query tile 平均约有 118 个精确块，仅精确块循环就有约 190 万次累积器乘法。固定偏移新增的开销只有一项：循环开始前每行读一个 FP32 的上一步 LSE，每个 tile 共 512 字节。QK、逐个 score 的 exp⁡2\exp_2exp2​、行求和、PV、用本步分母做的最终归一化、新 LSE 的 log⁡2ℓ\log_2\elllog2​ℓ，以及循环结束后的范围检查都保留。

固定偏移还缩短了依赖链：

online:  S ──> row max ──> m_new ──> exp2(S - m_new) ──> P·V ──┐
                             └──> alpha ──> scale old O ───────┴──> O
fixed:   S ──────────────────────> exp2(S - prior) ──> P·V ──────> O

在 online 版本中，pijp_{ij}pij​ 要等本 tile 的行最大值归约完成才能计算；新的 PV 累加进 OOO 之前，旧的 OOO 要先乘以 α\alphaα。QK 和 PV 在 Tensor Core 上执行，求最大值、归约和逐行缩放在普通执行单元和 SFU 上执行。后面这几步夹在两次矩阵乘之间，会拉长关键路径。使用固定偏移后，依赖链只剩 S→exp⁡2→PVS\to\exp_2\to PVS→exp2​→PV，更容易与数据搬运和下一轮 QK 重叠。

ccc 是第 1 节中的每行偏移，在 EchoSparse 中是自然对数单位的上一步 LSE，ci=(ln⁡2) a^ic_i=(\ln2)\,\hat a_ici​=(ln2)a^i​；下面的等价关系对任何固定偏移都成立。QK∗⊤QK_*^\topQK∗⊤​ 的 6 列就是三个小矩阵乘各自的列；指数和 token 数修正都是逐元素的。把 WWW 按列写成 [W1 W2 W3][W_1\ W_2\ W_3][W1​ W2​ W3​]，有

WV∗=W1vˉ1⊤+W2vˉ2⊤+W3V3(4),W1=W11+W21+W31, WV_*=W_1\bar v_1^\top+W_2\bar v_2^\top+W_3V_3^{(4)},\qquad W\mathbf 1=W_1\mathbf 1+W_2\mathbf 1+W_3\mathbf 1 , WV∗​=W1​vˉ1⊤​+W2​vˉ2⊤​+W3​V3(4)​,W1=W1​1+W2​1+W3​1,

即三个块对分子和分母的贡献都加进了同一个 N\mathcal NN、D\mathcal DD。n∗n_*n∗​ 必须随列一起进入分子和分母。精确 token 也累加进同一对 N\mathcal NN、D\mathcal DD，全部扫描完后只做一次除法。如果三个块各自做 softmax 再把输出相加，每块都会被归一化成 1，结果就不同了。

因此，在相同的稀疏计划、代表 K/V、token 数和统一归一化下，打包只改变计算的分组方式，数学上输出相同。EchoSparse 相对稠密计算的全部近似都来自上一节的代表压缩。浮点求和顺序的改变会带来细微的舍入差别。

6 列远不够填满一个 Tensor Core tile，实际需要跨很多块拼接。实验分支每次迭代处理 128 列：均值流一次拼接 128 个块的均值，四代表流一次拼接 32 个块、每块 4 列。每条流只有最后一次迭代需要掩码。

已发布版本没有做打包（图中标为 nonpacked），它有三个循环：第一个遍历精确块列表；第二个以 128 列为单位扫描全部块的均值，并用掩码屏蔽精确块和四代表块对应的列；第三个遍历四代表块列表，每块一个 id，展开成 4 列，列表补齐到固定宽度。在这次测试的计划中，每个 tile 要处理 1280 个均值列和 1536 个代表列，共 2816 列，平均只有 2129 列有用，约占 76%。被屏蔽的列可以不搬数据，但 MMA 按固定形状发射，这部分计算开销仍然存在。

实验分支的分组打包（grouped packing）为每个（query tile，head）生成两条紧凑的索引流，代码中称为 descriptor。均值流中一个块 id 对应一列；四代表流中一个块 id 对应 4 列，在片上按 4⋅block+sub4\cdot\text{block}+\text{sub}4⋅block+sub 展开地址。更早的逐列打包给每个代表列存一个索引，一个四代表块占 4 个 id，分组打包只存 1 个。未打包版本的四代表列表本来就是每块一个 id。两类来源分在两个循环里处理，混合 tile 也就不需要对两个源张量都做带掩码的加载。

打包只作用于索引。代表 K/V 没有复制成连续张量，每次迭代仍按索引从原位置读取（gather）。

5. 数据搬运与流水线

如果把每个 tile 用到的代表 K/V 复制成连续张量，就可以像精确块一样整块搬运。但复制本身要读一次、写一次，kernel 还要再读一次，而且每个（query tile，head）选中的块都不同。按每个 tile 平均 2129 列、每列 d+dv=256d+d_v=256d+dv​=256 个 BF16 估算，每个 tile 约 1.09 MB。591 个 query tile 乘以 40 个 head，逐 tile 复制一遍要写约 26 GB。作为对比，同一计划下 NCU 记录的主 kernel DRAM 读取总量约为 9.7 GB。

不复制时，小块搬运也有固定开销：descriptor 和地址计算、对齐、通知数据到达的 barrier，以及 shared memory 缓冲区。负载越零碎，这些开销越难分摊。因此需要先把有效列拼成足够宽的 tile，再让搬运和计算重叠。

设每次迭代的装载耗时为 tℓt_\elltℓ​、计算耗时为 tct_ctc​，共 nnn 次迭代。串行执行的总时间是 n(tℓ+tc)n(t_\ell+t_c)n(tℓ​+tc​)。假设每次迭代耗时恒定，且搬运与计算完全重叠，两级流水线的总时间约为

tℓ+(n−1) max⁡(tℓ,tc)+tc+tsync, t_\ell+(n-1)\,\max(t_\ell,t_c)+t_c+t_{\text{sync}}, tℓ​+(n−1)max(tℓ​,tc​)+tc​+tsync​,

首尾两项分别是流水线的填充和排空。不计 tsynct_{\text{sync}}tsync​ 时，n=1n=1n=1 退化为串行的 tℓ+tct_\ell+t_ctℓ​+tc​。tsynct_{\text{sync}}tsync​ 表示没有被隐藏的等待和 barrier 开销。nnn 较小时，填充和排空的占比较大。按前面的计数，每个 tile 的精确块循环约 118 次迭代，均值流约 6 次（709/128），四代表流约 12 次（355/32）。在 Wan2.1-14B 的形状下，按未打包基线实际执行的列数计，精确块循环约占 73%（7552/(7552+2816)7552/(7552+2816)7552/(7552+2816)；按分组打包的有用列计约占 78%）。所以流水线先加在精确块循环上。

H100 的 TMA（Tensor Memory Accelerator）用一个 descriptor 描述张量的形状，由专用硬件把整块数据异步搬进 shared memory。K、V 的布局是 [N,H,D]。一个 64-token 块是一个按原张量步长描述的矩形 tile（H>1H>1H>1 时在 token 方向不连续），用 block shape 为 [64,1,D] 的 descriptor 在行偏移 64⋅block64\cdot\text{block}64⋅block 处取出。

实验分支目前的做法是：精确块通过 TMA 加载，用三级软件流水线让搬运和 dot 重叠；代表列按分组打包的索引逐列读取。三级流水线由 Triton 的软件流水调度生成，三个 stage 是环形缓冲区的三个槽位。第 0 块计算完、槽位释放后，第 3 块才能装入同一个槽位；计算等待数据到达，装载等待槽位空出。只开 TMA、不加流水线时几乎没有收益（主 kernel 57.15 ms 对 57.22 ms），两者一起使用才有效。流水级数从 3 增加到 6，时间基本不变。

在同一 Wan2.1-14B 计划的 NCU 测量中，加入 TMA 后，指令数从 10.42 G 降到 9.79 G，主 kernel 耗时从 39.06 ms 降到 35.64 ms。barrier 和 wait 仍占约四成 warp 周期。搬运指令减少以后，同步仍是主要开销。

代表流可以改成生产者–消费者（producer–consumer）结构：生产者 warp 按分组打包的索引读取后续的代表列，在 shared memory 的三个槽位里整理成满宽的 tile；消费者 warp 对已就绪的槽位做 QK、exp⁡2\exp_2exp2​ 和 PV，累加进同一对 N\mathcal NN、D\mathcal DD，用完后释放槽位。消费者等待数据到达，生产者等待槽位空出。

Wan2.1-14B 生成整段视频的加速比在 B200 上是 1.70×，在 RTX 5090 上是 1.39×（同一模型单个稀疏步的 forward 为 1.61×）。两组评测的设置不同：RTX 5090 上每个模型只跑了一个提示词；Wan2.1-14B、HunyuanVideo 和 MiniMax-H3 还把权重放在 CPU 内存里，分组搬到 GPU 上计算（CPU offload）。因此这两个数不能直接当作两种硬件的对比。

7. 总结

视频扩散模型中，低权重的 KV 块数量很多，加起来仍会明显影响 softmax 的分子和分母。EchoSparse 用按 token 数加权的代表近似这些块，让它们和精确块留在同一个 softmax 里。1 列、4 列的代表可以拼成完整的 GEMM tile，与精确 token 共用分子和分母，打包前后的计算结果相同。相邻去噪步的 LSE 通常很接近，所以上一步的 LSE 可以作为固定偏移，去掉 online softmax 中求最大值和重缩放的步骤；上一步的块质量则决定每个块用多少代表。

完整的生产者–消费者打包路径还在研究中，尚未实现，也没有发布；H100 与 RTX 4090 的支持也尚未完成。
