EchoSparse：让上一步的统计量为下一步指路，用多层级近似代替丢弃，再把稀疏 attention 排得更紧

作者 EchoSparse Team

视频扩散模型的 self-attention 序列非常长。比如 Wan2.1-14B 生成 720p、81 帧的视频，单层 attention 要处理约 7.56 万个 token。对一个 query 来说，很多 KV 块的贡献很小。

LLM 上有不少高稀疏度的做法，比如滑动窗口（SWA），以及 GDN、KDA 这类线性 attention，但它们基本是在训练时就进入模型结构的。我们关心的是另一种情况：已经用 dense softmax 训好的视频 DiT，不重新训练，直接替换 attention。视频里一个 query 的概率质量往往分散在时空方向的很多块上，单个块很小，合起来不小。把这些块直接丢掉，分子和分母都会变，整行的加权方式也随之改变，在 training-free 替换中这通常会体现在生成画面上。训练阶段引入 SWA 或线性 attention 的视频模型属于另一类方法。

我们的工作是在 Haopeng Li 等人的 PISA（论文，代码）和 Sol-Attn（项目页，论文）的基础上继续做的。两者都是近似而不是丢弃：PISA 把 keep-or-drop 改成 exact-or-approximate，重要块精确计算，其余块用块内 Taylor 展开近似；Sol-Attn 给未选中的块加零阶补偿，并用同一个 token 对池化块的 score tile 做路由。补偿项都进入 attention 的分子和分母，多个块的代表向量也都已经拼起来做 GEMM。

EchoSparse 在此基础上做了三件事：

  1. 复用上一步的统计量。 去噪相邻两步里，每个 attention 行的统计量变化很小，所以上一步的 LSE（log-sum-exp）和各块的质量（block mass）可以在本步使用。LSE 作为 softmax 的固定偏移，FlashAttention 内循环里每个 KV tile 都要做的行最大值归约、缩放系数计算和旧累积量重缩放因此可以去掉；块质量给出块之间的相对重要性。
  2. 多层级代表块。 一个块的代表数 mbm_bmb​ 不必固定为 1，可以取 1、2、4、8 直到 64（即原始 token）这些档位，代表越多近似越细，开销也越大。当前实现只用了 1、4、64 三档。
  3. 代表块的 packing。 代表项的计算很零碎，例如 (Bq×d)(d×1)(B_q\times d)(d\times1)(Bq​×d)(d×1)、(Bq×d)(d×1)(B_q\times d)(d\times1)(Bq​×d)(d×1)、(Bq×d)(d×4)(B_q\times d)(d\times4)(Bq​×d)(d×4)。它们可以合成一个 (Bq×d)(d×[1+1+4])(B_q\times d)(d\times[1+1+4])(Bq​×d)(d×[1+1+4]) 的计算。但拼接、搬运和同步也有成本，需要把数据组织成足够宽的 tile，并让搬运和计算重叠。

PISA 实际使用的是逐块零阶加全局一阶。记 U\mathcal UU 为某个 query tile 的落选块集合。示意地写（满块、不考虑尾块），理想的逐块一阶项 ∑b∈UesˉbHb⊤q/d\sum_{b\in\mathcal U} e^{\bar s_b}H_b^\top q/\sqrt d∑b∈U​esˉb​Hb⊤​q/d​ 被换成 (∑b∈Uesˉb)Hˉ⊤q/d\bigl(\sum_{b\in\mathcal U} e^{\bar s_b}\bigr)\bar H^\top q/\sqrt d(∑b∈U​esˉb​)Hˉ⊤q/d​。求和只遍历 U\mathcal UU，而 Hˉ\bar HHˉ 是在整个序列上预先汇总的全局一阶统计量，不随每个 query 的 U\mathcal UU 重新计算；满块等长时可以理解为各块 HbH_bHb​ 的平均，生产代码对尾块另有按 count 的缩放。预处理时先形成每块的 HbH_bHb​ 再归约，attention 内循环只加载这一个全局矩阵。这也是一种近似。二阶方面，PISA 在相关工作中结合 Based、power attention 讨论过 Taylor 特征维度的膨胀；上表是我们按直接缓存方式算的代价，不代表 PISA 的 kernel 存储了逐块二阶张量。

EchoSparse 不提高展开阶数，而是把块分成更多组，每组仍用零阶近似，组数 mbm_bmb​ 可变（第 3 节）。

2. LSE 复用

FlashAttention 类 kernel 按 KV tile 扫描，用 online softmax 维护每行的运行最大值。实现中统一使用 exp⁡2\exp_2exp2​，本节的 sijs_{ij}sij​ 都已乘过 log⁡2e\log_2 elog2​e。每个 KV tile，每行 iii 要做：

minew=max⁡(mi, max⁡jsij),αi=2 mi−minew,pij=2 sij−minew,ℓi←αi ℓi+∑jpij,Oi←αi Oi+∑jpijvj. \begin{aligned} m_i^{\text{new}}&=\max\bigl(m_i,\ \max_j s_{ij}\bigr),\qquad \alpha_i=2^{\,m_i-m_i^{\text{new}}},\qquad p_{ij}=2^{\,s_{ij}-m_i^{\text{new}}},\\ \ell_i&\leftarrow\alpha_i\,\ell_i+\sum_j p_{ij},\qquad O_i\leftarrow\alpha_i\,O_i+\sum_j p_{ij}v_j . \end{aligned} minew​ℓi​​=max(mi​, jmax​sij​),αi​=2mi​−minew​,pij​=2sij​−minew​,←αi​ℓi​+j∑​pij​,Oi​←αi​Oi​+j∑​pij​vj​.​

如果每行有一个事先给定的固定偏移 a^i\hat a_ia^i​，循环变成

pij=2 sij−a^i,ℓi←ℓi+∑jpij,Oi←Oi+∑jpijvj. p_{ij}=2^{\,s_{ij}-\hat a_i},\qquad \ell_i\leftarrow\ell_i+\sum_jp_{ij},\qquad O_i\leftarrow O_i+\sum_jp_{ij}v_j . pij​=2sij​−a^i​,ℓi​←ℓi​+j∑​pij​,Oi​←Oi​+j∑​pij​vj​.

EchoSparse 取 a^i\hat a_ia^i​ 为上一去噪步同层、同 CFG 分支、同一行的 log2 LSE。下面比较固定偏移路径与 online 回退路径。

取 BM=128、BN=64、D=Dv=128，scale2=log2(e)/sqrt(D)；原始 token 的 log_count 为 0，代表项为 log⁡2n\log_2 nlog2​n。主线 SM120 将 64-token 块分成两个 32-key 半块，H100 实验路径使用 64 宽 tile。

# Online softmax
m = tl.full((BM,), -float("inf"), tl.float32)
l = tl.zeros((BM,), tl.float32)
acc = tl.zeros((BM, Dv), tl.float32)
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    block_max = tl.max(s2, axis=1)
    m_new = tl.maximum(m, block_max)
    alpha = tl.exp2(m - m_new)
    p = tl.exp2(s2 - m_new[:, None])
    l = l * alpha + tl.sum(p, axis=1)
    acc = acc * alpha[:, None]
    acc = tl.dot(p.to(tl.bfloat16), v, acc)
    m = m_new
out = acc / l[:, None]
new_lse2 = m + tl.log2(l)

# Fixed offset
prior2 = tl.load(PREV_LSE2 + rows * H + head)
l = tl.zeros((BM,), tl.float32)
acc = tl.zeros((BM, Dv), tl.float32)
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    p = tl.exp2(s2 - prior2[:, None])
    l += tl.sum(p, axis=1)
    acc = tl.dot(p.to(tl.bfloat16), v, acc)
out = acc / l[:, None]
new_lse2 = prior2 + tl.log2(l)

每个 KV tile 省掉的是：

  • 行最大值归约：128 行、每行 64 个元素的 max，逻辑上约 128×63128\times63128×63 次比较及 lane 间归约，另有 128 次运行最大值比较。
  • 缩放系数：128 个 αi=2mi−minew\alpha_i=2^{m_i-m_i^{\text{new}}}αi​=2mi​−minew​。128×64=8192128\times64=8192128×64=8192 个 pijp_{ij}pij​ 的 exp⁡2\exp_2exp2​ 仍然要算。
  • 旧累积量重缩放：分母 128 个元素，输出累积器 128×128=16,384128\times128=16{,}384128×128=16,384 个 FP32 元素。

这些是逻辑工作量，不等于机器指令数；累积器在片上，也不对应显存流量。它们随 KV tile 数重复发生：密度 0.10 时每个 query tile 平均约 118 个 exact 块，仅 exact 循环就有约 190 万次累积器乘法。新增的只是循环前每行读一个 FP32 的历史 LSE，每个 tile 512 字节。QK、逐 score 的 exp⁡2\exp_2exp2​、行和、PV、用本步分母做的最终归一化、新 LSE 的 log⁡2ℓ\log_2\elllog2​ℓ 以及循环后的范围检查都保留。

另一个收益来自依赖关系：

online:  S ──> row max ──> m_new ──> exp2(S - m_new) ──> P·V ──┐
                             └──> alpha ──> scale old O ───────┴──> O
fixed:   S ──────────────────────> exp2(S - prior) ──> P·V ──────> O

online 版本中，pijp_{ij}pij​ 要等本 tile 的行最大值归约完成；新的 PV 累加进 OOO 之前，旧 OOO 要先乘 α\alphaα。QK、PV 在 Tensor Core 上执行，max、归约和逐行缩放在普通执行单元和 SFU 上执行，这两段夹在矩阵乘之间会拉长关键路径。固定偏移后只剩 S→exp⁡2→PVS\to\exp_2\to PVS→exp2​→PV，更容易与搬运和下一轮 QK 重叠。

B200 上，当前固定偏移的 CuTe DSL 实现把 OOO 放在 TMEM 中，所有 PV 的 MMA 都直接累加到同一块 tO，只在第一次清零；循环中从 TMEM 读出 score，减去固定 LSE，做 exp⁡2\exp_2exp2​，转为 BF16 写回，再累加分母。循环结束后才把 OOO 读到寄存器、除以本步行和并写出输出和新 LSE（源码），中间没有逐轮的 OOO 行缩放。

固定偏移为什么不改变结果

因此，在相同的稀疏计划、代表 K/V、multiplicity 和统一归一化下，packing 只是重新分组，数学上输出相同，不引入新的近似；EchoSparse 相对 dense 的近似全部来自上一节的代表压缩。浮点求和顺序改变会带来细微的舍入差别。

6 列远不够一个 Tensor Core tile，实际要跨很多块填满。实验分支每次迭代处理 128 列：均值流一次拼 128 个块的均值，四代表流一次拼 32 个块、每块 4 列，只有每条流的最后一次需要 mask。

已发布的 nonpacked 路径有三个循环：exact 块列表；以 128 列为单位扫描全部块的均值，并 mask 掉 exact 块和四代表块对应的列；四代表块列表，每块一个 id、展开成 4 列，列表补到固定宽度。在这次测试的计划里，每个 tile 要走 1280 个均值列和 1536 个代表列，共 2816 列，平均有用的只有 2129 列，约 76%。被 mask 的列可以不搬数据，但 MMA 按固定形状发射，这部分开销仍然存在。

实验分支的 grouped packing 为每个（query tile, head）生成两条紧凑的 descriptor 流：均值流一个块 id 对应一列；四代表流一个块 id 对应 4 列，在片上按 4⋅block+sub4\cdot\text{block}+\text{sub}4⋅block+sub 展开地址。更早的逐列 packed 流给每个代表列存一个索引，一个四代表块占 4 个 id，grouped 只存 1 个；nonpacked 的四代表列表本来就是每块一个 id。两类来源分在两个循环里，混合 tile 也不必对两个源张量都做 masked load。

打包的是 descriptor 和索引，代表 K/V 本身没有复制成连续张量，每次迭代仍按索引 gather。

5. 搬运与流水

把每个 tile 用到的代表 K/V 复制成连续张量，可以像 exact 块一样整块搬运，但复制本身要读一次、写一次，kernel 还要再读一次；而且每个（query tile, head）的选择都不同。按平均每个 tile 2129 列、每列 d+dv=256d+d_v=256d+dv​=256 个 BF16 估算，每个 tile 约 1.09 MB，591 个 query tile 乘 40 个 head，逐 tile 物化一遍要写约 26 GB，而同一计划下 NCU 记录的主 kernel DRAM 读取总量约 9.7 GB。

不复制时，小块搬运也有固定开销：descriptor 和地址计算、对齐、通知数据到达的 barrier，以及 shared memory 缓冲区。负载越零碎，这些开销越难摊销。所以需要先把有效列凑成足够宽的 tile，再让搬运和计算重叠。

设每次迭代装载耗时 tℓt_\elltℓ​、计算耗时 tct_ctc​，共 nnn 次迭代。串行是 n(tℓ+tc)n(t_\ell+t_c)n(tℓ​+tc​)。假设每次迭代耗时恒定、搬运与计算理想重叠，两级流水的总时间约为

tℓ+(n−1) max⁡(tℓ,tc)+tc+tsync, t_\ell+(n-1)\,\max(t_\ell,t_c)+t_c+t_{\text{sync}}, tℓ​+(n−1)max(tℓ​,tc​)+tc​+tsync​,

首尾两项是填充和排空，不计 tsynct_{\text{sync}}tsync​ 时，n=1n=1n=1 退化为串行的 tℓ+tct_\ell+t_ctℓ​+tc​；tsynct_{\text{sync}}tsync​ 表示未被隐藏的等待和 barrier 开销。nnn 小时填充和排空占比大。按前面的计数，每个 tile 的 exact 循环约 118 次迭代，均值流约 6 次（709/128），四代表流约 12 次（355/32）。在 Wan2.1-14B 的形状下，按 nonpacked 基线的执行列计，exact 循环约占 73%（7552/(7552+2816)7552/(7552+2816)7552/(7552+2816)；按 grouped 的有用列计约 78%），所以先在 exact 循环上做流水。

H100 的 TMA（Tensor Memory Accelerator）用一个 descriptor 描述张量形状，由专用硬件把整块数据异步搬进 shared memory。K、V 的布局是 [N,H,D]，一个 64-token 块是按原张量步长描述的矩形 tile（H>1H>1H>1 时在 token 方向不连续），用 block shape 为 [64,1,D] 的 descriptor 在行偏移 64⋅block64\cdot\text{block}64⋅block 处取出。

实验分支目前的做法是：exact 块经 TMA 加载，三级软件流水让搬运与 dot 重叠，代表列按 grouped descriptor 做指针 gather。三级流水由 Triton 的软件流水调度生成，三个 stage 是环形缓冲区的三个槽位：第 0 块被消费、槽位释放后，第 3 块才能装入同一槽位；计算等数据到达，装载等槽位空出。只开 TMA 不加流水时几乎没有收益（主 kernel 57.15 ms 对 57.22 ms），两者组合才有效；流水级数从 3 加到 6，时间基本不变。

同一 Wan2.1-14B 计划的 NCU 测量中，加入 TMA 后，指令数从 10.42 G 降到 9.79 G，主 kernel 耗时从 39.06 ms 降到 35.64 ms。barrier 和 wait 仍占约四成 warp 周期，搬运指令减少后，同步仍是主要开销。

代表流可以组织为 producer–consumer：producer warp 按 grouped descriptor gather 后续代表列，在 shared memory 的三个槽位里整理成满宽 tile；consumer warp 对已就绪的槽位做 QK、exp⁡2\exp_2exp2​ 和 PV，累加进同一对 N\mathcal NN、D\mathcal DD，用完后交还槽位。consumer 等数据到达，producer 等槽位空出。

7. 总结

视频扩散模型的 attention 更适合近似而不是丢弃：低权重的块数量多，合起来仍影响分子和分母，用 count 加权的代表把它们留在同一个 softmax 里，而不是清零。近似也不必带来零碎计算，1 列、4 列的代表可以拼成完整的 GEMM tile，与 exact token 共用分子和分母，结果不变。相邻去噪步的 LSE 通常接近，上一步的 LSE 可以作为固定偏移，去掉 online softmax 的 max 和 rescale，块质量则决定每个块用多少代表。

完整的 packed producer–consumer 路径还在探索，尚未实现和 release；H100 与 RTX 4090 的支持也尚未完成。
