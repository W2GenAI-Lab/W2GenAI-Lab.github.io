EchoSparse：让上一步的统计量为下一步指路，用多层级近似代替丢弃，再把稀疏 attention 排得更紧

作者 EchoSparse Team

视频扩散模型的 self-attention 序列很长。Wan2.1-14B 生成 720p、81 帧的视频，单层 attention 要处理约 7.56 万个 token，一次前向要过几十层，一段视频要去噪 50 步。对某个 query 来说，大部分 KV 块的贡献都很小，看上去大可以丢掉。

在 LLM 里，这条路已经有不少成功的设计：滑动窗口（SWA）、各种稀疏访问，还有 GDN、KDA 这类线性 attention 的状态更新。不过它们大多是训练进模型结构里的。我们面对的是另一个更挑剔的设定：拿一个已经用 dense softmax 训练好的视频 DiT，不重训，直接把 attention 换掉。视频里一个 query 的概率质量常常散在空间和时间方向的很多块上，单独看每一块都很弱，合起来却不小；把它们直接清零，变的不只是分子，还有分母，也就是整行的加权方式。在这种 training-free 替换里，硬丢弃往往先在画面上露馅。这并不是说 trainable 的 SWA 或线性 attention 在视频上行不通，不少主流视频模型已经加入了局部窗口一类的机制，只是那是另一条路线。

所以我们选择把不重要的块算得粗一点，而不是一律清零。这个思路不是我们首先提出的。EchoSparse 是在 Haopeng Li 等人的 PISA（论文，代码）和 Sol-Attn（项目页，论文）的基础上继续做的。PISA 把常见的 keep-or-drop 换成 exact-or-approximate：重要块精确计算，其余块用块内 Taylor 展开近似。Sol-Attn 同样给未选中的块加零阶补偿，并且复用同一个 token 对池化块的 score tile 来做路由。两者都把补偿项放进 attention 的分子和分母，也都已经把多个块的代表向量拼起来做 GEMM。

EchoSparse 在这条线上又往前走了三步：

  1. 时间上的统计量。 去噪相邻两步里，每个 attention 行的统计量变化不大，所以上一步留下的 LSE（log-sum-exp）和各块的质量（block mass）可以在本步一起用：LSE 当作 softmax 的固定偏移，块质量给出“哪些块相对重要”的排序。
  2. 多层级近似，而不是丢弃。 一个块的代表数 mbm_bmb​ 不必固定为 1。从 1、2、4、8 一直到 64（也就是原始 token），这是一组由粗到细的分辨率档位。当前实现用了其中 1、4、64 三档，把列预算花在更值得的块上。
  3. 执行与布局。 代表项天然零碎：一个块 1 列，另一个块 4 列。它们可以拼成更宽的 GEMM，但拼接、搬运和同步本身也有成本，需要按 GPU 的方式组织数据和流水线。

说得更直白一点。第一，FlashAttention 内循环里每个 KV tile 都要做的“行最大值归约、缩放系数、旧累积量重缩放”，有了固定偏移可以整段删掉。第二，代表数从 1 到 4 再到 64，是一个按块调节精度和开销的旋钮。第三，许多 (Bq×d)(d×1)(B_q\times d)(d\times1)(Bq​×d)(d×1)、(Bq×d)(d×4)(B_q\times d)(d\times4)(Bq​×d)(d×4) 这样的小乘法要聚成足够宽的 tile，再让搬运和计算重叠起来。代码在这里：W2GenAI-Lab/EchoSparse-Attn。

先交代范围。主线目前支持 B200（SM100）和 RTX 5090（SM120），H100（SM90）和 RTX 4090 的正式适配还在 TODO 里。文中 grouped 代表描述符、TMA 与三级流水的内容来自 H100 实验分支，没有合入主线，涉及的地方我会标出来。

只看一行 query qqq。块里有 nbn_bnb​ 个有效 token（通常 nb=Bkn_b=B_knb​=Bk​，尾块可能更少），令

PISA 的处理很聪明。它实际的 hybrid 是逐块零阶加全局一阶。记 U\mathcal UU 为某个 query tile 的落选块集合。示意地写（满块、不考虑尾块），理想的逐块一阶项 ∑b∈UesˉbHb⊤q/d\sum_{b\in\mathcal U} e^{\bar s_b}H_b^\top q/\sqrt d∑b∈U​esˉb​Hb⊤​q/d​ 被换成 (∑b∈Uesˉb)Hˉ⊤q/d\bigl(\sum_{b\in\mathcal U} e^{\bar s_b}\bigr)\bar H^\top q/\sqrt d(∑b∈U​esˉb​)Hˉ⊤q/d​。求和只遍历 U\mathcal UU，但 Hˉ\bar HHˉ 是在整个序列上预先汇总好的全局一阶统计量，不随每个 query 的 U\mathcal UU 重新计算；满块等长时可以把它理解成各块 HbH_bHb​ 的平均，生产代码对尾块另有按 count 的缩放。预处理时会先形成每块的 HbH_bHb​ 再归约，但 attention 内循环只需要加载这一个全局矩阵，不必流式搬运每块的 HbH_bHb​。这当然也是近似。至于二阶，PISA 在相关工作里结合 Based、power attention 讨论过 Taylor 特征维度的膨胀；上面那张表是我们自己的整理，用来说明为什么不直接往高阶走，并不代表 PISA 的 kernel 存了逐块的二阶张量。

EchoSparse 走的是另一个方向：不升阶，而是把块切细。每一组仍然只用零阶摘要，但组数 mbm_bmb​ 可以变，这是第 3 节的内容。在那之前，先把 softmax 本身的内循环理顺。

2. LSE 复用：内循环里到底删掉了什么

FlashAttention 一类的 kernel 按 KV tile 扫描，用 online softmax 维护每行的运行最大值。写成 base-2 的形式（实现里都是 exp⁡2\exp_2exp2​，本节的 sijs_{ij}sij​ 都已乘过 log⁡2e\log_2 elog2​e），每来一个 KV tile，每行 iii 要做：

minew=max⁡(mi, max⁡jsij),αi=2 mi−minew,pij=2 sij−minew,ℓi←αi ℓi+∑jpij,Oi←αi Oi+∑jpijvj. \begin{aligned} m_i^{\text{new}}&=\max\bigl(m_i,\ \max_j s_{ij}\bigr),\qquad \alpha_i=2^{\,m_i-m_i^{\text{new}}},\qquad p_{ij}=2^{\,s_{ij}-m_i^{\text{new}}},\\ \ell_i&\leftarrow\alpha_i\,\ell_i+\sum_j p_{ij},\qquad O_i\leftarrow\alpha_i\,O_i+\sum_j p_{ij}v_j . \end{aligned} minew​ℓi​​=max(mi​, jmax​sij​),αi​=2mi​−minew​,pij​=2sij​−minew​,←αi​ℓi​+j∑​pij​,Oi​←αi​Oi​+j∑​pij​vj​.​

如果事先有一个每行固定的偏移 a^i\hat a_ia^i​，循环就只剩

pij=2 sij−a^i,ℓi←ℓi+∑jpij,Oi←Oi+∑jpijvj. p_{ij}=2^{\,s_{ij}-\hat a_i},\qquad \ell_i\leftarrow\ell_i+\sum_jp_{ij},\qquad O_i\leftarrow O_i+\sum_jp_{ij}v_j . pij​=2sij​−a^i​,ℓi​←ℓi​+j∑​pij​,Oi​←Oi​+j∑​pij​vj​.

EchoSparse 取 a^i\hat a_ia^i​ 为上一去噪步同层、同 CFG 分支、同一行的 log2 LSE。下面是去掉索引、mask 和块质量写回之后的 Triton 风格对比（对应主线的固定偏移路径和 online 回退路径），形状取 BM=128、BN=64、D=Dv=128。主线 SM120 实际把一个 64-token 块拆成两个 32-key 的半块来走，H100 实验分支是 64 宽。exact token 的 log_count 为 0，代表项为 log⁡2n\log_2 nlog2​n，同一段代码都适用。这不是可以直接编译的完整 kernel。

# q: [BM, D]  k: [BN, D]  v: [BN, Dv]  s2, p: [BM, BN]  m, l, prior2: [BM]  acc: [BM, Dv]
# scale2 = log2(e) / sqrt(D); prior2 is a log2 LSE, in the same units as exp2

# online softmax: m = -inf, l = 0, acc = 0
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    block_max = tl.max(s2, axis=1)            # [BM] row reduction
    m_new = tl.maximum(m, block_max)          # [BM]
    alpha = tl.exp2(m - m_new)                # [BM] extra exp2
    p = tl.exp2(s2 - m_new[:, None])          # [BM, BN] waits for m_new
    l = l * alpha + tl.sum(p, axis=1)         # rescale old denominator
    acc = acc * alpha[:, None]                # rescale old O: BM*Dv FP32
    acc = tl.dot(p.to(tl.bfloat16), v, acc)
    m = m_new
out = acc / l[:, None]
new_lse2 = m + tl.log2(l)

# fixed offset: one load of the previous LSE per query row, before the KV loop
prior2 = tl.load(PREV_LSE2 + rows * H + head)  # [BM]
l = tl.zeros((BM,), tl.float32)
acc = tl.zeros((BM, Dv), tl.float32)
for k, v, log_count in kv_tiles:
    s2 = tl.dot(q, tl.trans(k)) * scale2 + log_count[None, :]
    p = tl.exp2(s2 - prior2[:, None])         # [BM, BN]
    l += tl.sum(p, axis=1)
    acc = tl.dot(p.to(tl.bfloat16), v, acc)   # accumulate straight into O
out = acc / l[:, None]                        # current denominator
new_lse2 = prior2 + tl.log2(l)

对照着数一下，每个 KV tile 删掉的是：

  • 行最大值归约：128 行、每行长度 64 的 max，逻辑上约 128×63128\times63128×63 次比较和相应的 lane 间归约，外加 128 次运行最大值的比较。

                             └──> alpha ──> scale old O ───────┴──> O

一条是 pijp_{ij}pij​ 要等本 tile 的行最大值归约完才能算；另一条是新的 PV 累加进 OOO 之前，旧 OOO 必须先乘完 α\alphaα。QK 和 PV 交给 Tensor Core，max、归约和逐行缩放走普通执行单元和 SFU，吞吐和并行方式都不同，夹在两次矩阵乘之间就会拉长关键路径。固定偏移之后，链只剩 S→exp⁡2→PVS\to\exp_2\to PVS→exp2​→PV，更容易和搬运、下一轮 QK 重叠。（这不是说下一轮 QK 一定要等 OOO 缩放完，有的 kernel 会提前发 QK；能确定的是上面这两条依赖。）

在 B200 上，这个差别更具体。当前固定偏移的 CuTe DSL 实现把 OOO 放在 TMEM（tensor memory）里，所有 PV 的 MMA 都直接累加到同一块 tO 上，只在第一次清零。循环里 score 从 TMEM 读出、减去固定 LSE、做 exp⁡2\exp_2exp2​、转成 BF16 写回，然后只加分母；整个循环结束后，才把 OOO 从 TMEM 读到寄存器，除以本步的行和，写出输出和新的 LSE（源码）。中间没有逐轮的 OOO 行缩放路径。至于和 FA4 相比到底少了多少次 TMEM 读写，需要反汇编或 NCU 归因才能回答，我们没有做，也就不给数字；score 的 TMEM 读取、P 的写回和相应的 barrier 照常存在。

所以，在相同的稀疏 plan、代表 K/V、multiplicity 和统一归一化下，packing 是一次等价重组，实数算术下输出相同，不引入新的算法近似；EchoSparse 相对 dense 的近似全部来自上一节的代表压缩。浮点求和的顺序变了，舍入会有细微差别，所以并不是 bitwise 相同。

当然，6 列远不是一个 Tensor Core tile。真正有意义的是跨很多块持续地凑：实验分支每次迭代处理 128 列，均值流一次拼 128 个块的均值，四代表流一次拼 32 个块、每块 4 列。这样每次 MMA 的列基本是满的，只有每条流的最后一次需要 mask。

对照一下已发布的 nonpacked 路径。它是三个循环：一个遍历 exact 块列表；一个以 128 列为单位扫描全部块的均值，其中 exact 块和四代表块对应的列被 mask 掉；一个遍历四代表块列表，每块一个 id、展开成 4 列，列表补到固定宽度。在这次测试的计划里，每个 tile 按这个布局要走 1280 个均值列加 1536 个代表列，共 2816 列，而真正有用的平均只有 2129 列，约 76%。被 mask 的列可以不搬数据，但 MMA 按固定形状发射，这些列的发射和计算开销照付。

实验分支的 grouped packing 就是这种重组的一个实现。一个小 kernel 为每个（query tile, head）生成两条紧凑的 descriptor 流：均值流一个块 id 对应一列；四代表流一个块 id 对应 4 列，在片上按 4⋅block+sub4\cdot\text{block}+\text{sub}4⋅block+sub 展开地址。和更早的“逐列 packed 流”相比，后者给每个代表列各存一个索引，一个四代表块占 4 个 id，grouped 只存 1 个；nonpacked 的四代表列表本来就是每块一个 id，不在这个比较里。两类来源分在两个循环里，混合 tile 也就不必对两个源张量都做 masked load。

要强调的是，被打包的是 descriptor 和索引，代表 K/V 本身并没有被复制成一个连续的大张量，每次迭代仍按索引 gather。为什么不干脆复制过去？这要看搬运的账。

5. 搬运与流水：拼接本身并不免费

直觉上，把每个 tile 要用的代表 K/V 复制成一个连续张量，就可以像 exact 块一样整块搬，问题好像就解决了。可复制本身是一次读加一次写，之后 kernel 还得再读一遍。更麻烦的是，选择对每个（query tile, head）都不一样。粗算一下：每个 tile 平均约 2129 列，每列 d+dv=256d+d_v=256d+dv​=256 个 BF16，约 1.09 MB；591 个 query tile 乘 40 个 head，按 tile 物化一遍要写约 26 GB。而同一 plan 下 NCU 记录的主 kernel DRAM 读取总共只有约 9.7 GB。这只是量级估计，但足以说明“先拷成连续张量”不能天真地做。

即使数据就在手边，小块搬运也有固定开销：每次发出搬运要准备 descriptor 和地址，要满足对齐，要用 barrier 通知消费者数据到了，还要在 shared memory 里留出缓冲区。负载越零碎，这些固定成本越难摊销。所以要先把有效列凑成像样的 tile，再让搬运和计算重叠，两件事缺一不可。

重叠的收益可以用一个简单模型看。每次迭代装载耗时 tℓt_\elltℓ​、计算耗时 tct_ctc​，共 nnn 次迭代。串行是 n(tℓ+tc)n(t_\ell+t_c)n(tℓ​+tc​)；假设每次迭代耗时恒定、搬运与计算可以理想重叠，两级流水的稳态每次接近 max⁡(tℓ,tc)\max(t_\ell,t_c)max(tℓ​,tc​)，总时间大约是

tℓ+(n−1) max⁡(tℓ,tc)+tc+tsync, t_\ell+(n-1)\,\max(t_\ell,t_c)+t_c+t_{\text{sync}}, tℓ​+(n−1)max(tℓ​,tc​)+tc​+tsync​,

首尾两项是填充和排空，n=1n=1n=1 时正好退回串行的 tℓ+tct_\ell+t_ctℓ​+tc​；tsynct_{\text{sync}}tsync​ 代表没能被隐藏的等待、barrier 等开销。nnn 小的时候，填充和排空占比就大。按上面的计数，每个 tile 的 exact 循环约 118 次迭代，均值流只有约 6 次（709/128），四代表流约 12 次（355/32）。这也是 exact 循环被先优化的原因：在 Wan2.1-14B 的形状下，按 nonpacked 基线的执行列计，它约占 73%（7552/(7552+2816)7552/(7552+2816)7552/(7552+2816)；按 grouped 的有用列计约 78%），流水线在那里最有用武之地。这只是性能模型，不是实测时序，也不是什么必然的加速定律。

H100 有 TMA（Tensor Memory Accelerator）：用一个 descriptor 描述张量形状，由专门的硬件异步把整块数据搬进 shared memory。exact 块恰好适合。K、V 的布局是 [N,H,D]，一个 64-token 块是按原张量步长描述的一块矩形 tile（H>1H>1H>1 时它在 token 方向并不连续），用 block shape 为 [64,1,D] 的 descriptor，在行偏移 64⋅block64\cdot\text{block}64⋅block 处一次取走。

实验分支现在实现的是：exact 块经 TMA 加载，三级软件流水让搬运与 dot 重叠，代表列按 grouped descriptor 做指针 gather。三级流水由 Triton 的软件流水调度生成，三个 stage 是环形缓冲区的三个槽位，不是三组分工不同的 warp，也不是三个 kernel。单独打开 TMA 而不加流水几乎没有收益（57.15 ms 对 57.22 ms），两者组合才快。流水再加深也没用，3 到 6 级的时间几乎一样，剩下的停顿主要来自同步，而不是预取不够。

NCU 给了一点机制上的证据。在同一个 Wan2.1-14B plan 上，从三级流水到 TMA 加三级流水，执行指令从 10.42 G 降到 9.79 G，tensor pipe active 从 38.95% 升到 42.69%，barrier 停顿从 17.86% 升到 22.57%，wait 从 21.13% 降到 18.63%，主 kernel 在这次 NCU profiling 里的耗时从 39.06 ms 降到 35.64 ms，这和表里 71.65→44.51 ms 的完整 GPU 流程计时不是同一种测量。地址计算少了，同步依然显著，barrier 和 wait 加起来仍占约四成 warp 周期。tensor pipe active 是 Tensor Core 管线忙碌的时间比例，不是 MFU，我们也没有测 MFU。

下一步想做的是代表流本身的 producer–consumer。设想是这样的：专门的 producer warp 按 grouped descriptor 去 gather 后续的代表列，在 shared memory 的三个槽位里整理成满宽的 tile；consumer warp 只管对已就绪的槽位做 QK、exp⁡2\exp_2exp2​ 和 PV，累加进同一对 N\mathcal NN、D\mathcal DD；用完的槽位交还 producer，继续装下一批。依赖还是那两类：consumer 等“数据到了”，producer 等“槽位空了”，不能覆盖还在被读的槽位。本质上是一个异步的环形队列，图 5 那条时间线换成两组独立的 warp 来跑。

这一步还没有实现，也没有 release。在 Triton 3.6 的 SM90 路径上，warp_specialize=True 被接受但没有效果，寄存器（254）、shared memory（131,104 B）和时间都和普通软件流水一样；这个版本也没有 tl.async_task，写不出真正的 warp 分工。我们还写过一个显式三槽 cp.async 环形缓冲加 WMMA 的手写原型，8 个 warp 既搬也算，结果是 18.0 ms 对 Triton 的 2.48 ms，而且有正确性 bug，只能算工具链验证。WMMA 的累积器是逐 warp 的片段，表达不了 FlashAttention-3 那种一个 warpgroup 发整块 MMA 的结构，需要手写 wgmma 或 CuTe 内核，那是后续工作。

7. 现状与后续

已经在主线里的：固定偏移的 LSE 复用、块质量反馈、1/4/64 三档代表和 query 度量聚类，B200 与 RTX 5090 的结果（含端到端生成）在主线 README 里。只在 H100 实验分支里的：grouped descriptor、exact 块的 TMA 加载和三级软件流水，需要显式打开，尚待集成进主线并补齐多模型 benchmark。还没有实现的：真正独立的 producer–consumer 代表流，以及 2、8、16、32 这些中间档位的代表数。最新主线也还没有正式的 RTX 4090（SM89）后端，需要单独适配与验收，H100 的 TMA 路径不能直接搬到 Ada 上；动画里的历史 RTX 4090 数据属于另一批实验，和本文的 H100 测试不是同一个口径。

回头看，三件事其实是同一个公式的三个侧面。上一步的统计量让 softmax 免去 max 与 rescale，也给分辨率分配提供了排序；count 加权的统一 softmax 让一个块可以用 1、4 或 64 列参与，而不必被清零；也正因为所有项共用一对分子分母，packing 只需要关心“同一组项怎么排”。数学上的等价，是我们敢大胆重排数据和流水线的底气。
